# NullBoard 长期路线

## 目标：让陌生人愿意点 Star

NullBoard 的吸引力来自「完全没有功能」这个玩笑。每天的小改动都应让项目更有趣、更容易理解、更值得展示或分享，同时保持足够可靠，让访客愿意收藏、贡献或推荐。

优先级：一眼看懂的笑点 → 值得转发的体验 → 易上手的开源项目 → 持续质量。Star 是结果信号，不保证增长数字，不刷星、不买星，也不靠骚扰式推广。

保留轻量的 React 前端，不引入真实任务管理、账号、后端或数据收集。下面是滚动路线，按访客反馈和实际效果调整；每次只提交一个可独立验证、可回退的改动，直接提交到 main，不强推、不绕过保护。

## 第一阶段：让人看懂并笑出来（第 1–2 周）

- [x] 替换过时的 CRA 示例测试，覆盖真实页面、主题切换和五个假功能。
- [x] 支持 Escape 关闭提示，恢复触发按钮焦点；保留常驻状态区域，改善可访问性基础。
- [ ] 给五个假功能设计不同的幽默反馈，让每次点击有发现感。
- [ ] 将重复按钮整理为数据驱动组件，让新增笑点更容易测试。
- [ ] 更新 README 的首屏介绍、真实截图和运行步骤，让访客 30 秒内理解项目。
- [ ] 更新浏览器标题、描述和默认图标，避免展示时仍像 CRA 模板。
- [ ] 为主题切换增加明确的无障碍名称与状态。

## 第二阶段：做一个值得展示的体验（第 3–4 周）

- [ ] 加入一个有记忆点的轻量彩蛋，例如永远完不成的「虚无进度」或零成就面板。
- [ ] 设计适合截图的页面布局与文案，手机上也能完整展示笑点。
- [ ] 增加用户主动触发的文案或链接复制，反馈复制成功或失败；不自动向第三方发布。
- [ ] 检查窄屏、大字号、明暗主题对比度、焦点样式和触控尺寸。
- [ ] 补充反复点击、关闭重开、主题切换和刷新流程的浏览器检查。
- [ ] 建立测试与构建检查，避免小更新破坏首次体验。

## 第三阶段：让开源参与也有趣（第 2 个月）

- [ ] 增加中英文切换，让两种语言的访客都能理解笑点。
- [ ] 编写轻量贡献指南，说明如何添加一个假功能、幽默反馈或翻译。
- [ ] 增加适合新贡献者的小问题清单和明确验收标准。
- [ ] 在 README 展示最佳彩蛋、快捷体验说明与开发方式；演示部署需另行决定。
- [ ] 保持动效可关闭并尊重减少动态效果偏好，避免用特效妨碍交互。

## 第四阶段：保留真的受欢迎的东西（第 3 个月及以后）

- [ ] 每周记录可公开读取的 Star、Fork 和新 issue 数量，结合反馈判断哪些改动值得继续。
- [ ] 不把相关性当因果：小样本涨跌不证明某个功能有效，不做增长数字承诺。
- [ ] 优先处理真实反馈、使用障碍和回归；删除彩蛋或改变定位前先讨论。
- [ ] 每月回看页面复杂度、包体和依赖风险，保持快速、好懂和容易贡献。
- [ ] 根据反馈更新下一轮路线，而不是无限堆叠假功能。

## 每日交付约定

1. 从路线中选一个有真实价值的小目标，发现回归时优先修复。
2. 在 main 最新版本上工作，检查差异并运行适用测试；遇到他人的新提交先整合，不覆盖。
3. 只在发布成功且远端确认后汇报「已提交」，附几个字说明和提交链接。
4. 测试未运行、权限受阻或提交失败时如实说明，不用空提交或改注释凑次数。
5. 外部服务、费用、数据收集、推广发信和部署另行讨论。

## 本地验证

在 `nullboard/` 目录执行：

```sh
npm ci
CI=true npm test -- --watchAll=false --runInBand
npx tsc --noEmit
npx eslint src --max-warnings=0
npm run build
```

涉及交互或布局时另做浏览器检查。DOM 测试不能代替真实浏览器与屏幕阅读器验证。
